# Nunc 项目宪法

本文件定义当前产品范围、职责和取舍原则，依据用户于 2026-10-12 确认的范围判断。它用于解释和修订具体设计，不表示现有实现、未集成候选或历史测试已经满足这些原则。旧文档中的版本、实施状态、测试模型和单次任务配置仍需按各自时点理解；已完成的历史事实不重写。

## 1. 产品目的

Nunc 是 Pi 的会话内滚动上下文与工作记忆扩展。它使一个持续会话在有限上下文中保留当前及持续任务仍需要的工作状态，并控制维护及后续请求的成本。

近期历史、增量工作记忆和适用的工具结果清理共同服务这个目的。当前任务的有效目标、关键条件、限定和未完成义务不能因局部进展或下一次回答暂时不用而任意丢弃。没有继续用途的信息应允许退出；完整历史回忆、永久保留每项结果和任意未来问答覆盖不属于承诺。

任务确实需要的信息被遗漏仍属于质量退化，不能用“有限记忆”豁免，也不能为改善分数而改变评测条件。目标同时考虑任务连续性、输入占用、维护次数、费用和等待时间，不单独追求最大压缩率、最小代码量或某个 benchmark 分数。

## 2. 职责分工

- 模型判断内容：必要性、适用范围、修订、状态、保留与退役。代码不把正文变化、年龄或引用数直接解释为业务意义变化。
- Nunc 执行明确操作：冻结已交付来源、构造候选、验证结构和引用、执行预算、维护合法工具关联、投影有效 M 与获准清理、说明失败与观察限制。
- Pi 拥有会话、原始记录、持久化、队列、工具执行、认证、序列化、传输及原生压缩调度。Nunc 使用公开接口，不另建一套宿主。
- 主 Agent 使用普通工作工具完成业务任务，需要时显式读取资料。长期状态由正常代码、文档和其他产物承担，Nunc 不自动维护它们。

字段、模块和私有算法允许采用保持这些职责与当前公共合同的等价实现。出现于设计中的例子不自动成为固定业务实体、步骤或测试轨迹。

## 3. 信息和生命周期边界

来源限定为当前选定会话路径、已交付活动历史、有效指令和既有记忆。未来输入不提前消费；Nunc 不主动搜索业务资料或回读已经退休的历史。读取自身配置、策略和宿主提供的会话状态不属于主动业务检索。

记忆允许增量修改、合并、拆分和退役。未变内容复用；必要的修改不受永久 pin、隐含外键或历史引用计数阻止。M 是工作状态快照，不覆盖新的用户指令，也不取得 system/developer 权限。

原始记录不因清理而删除。无效、取消、冲突或未确认提交沿用已有保护，不启用半份变更。版本检查、来源绑定和完整提交是现有操作的必要约束，不构成新增锁、备份、审计数据库、回滚服务或自动重放系统的理由。

## 4. 清理、依赖与原文读取

工具清理属于已接受功能范围。保留机械清理、语义省略、摘要和声明引用，不能仅为代码更短而删除有价值的能力。

新清理必须依据本次最终保留的 M 和来源校验。程序不能先淘汰其声明的保留依据，再照样批准该项清理。非法单项不应用；合法 M 和其他有效清理不因此任意丢弃。

`memoryRefs` 表示批准该次清理时使用的记忆依据，不是要求所有后续记忆修改都撤销旧清理的永久外键。后续 M 的正文修改、删除或预算淘汰，不单独触发对已提交语义清理的自动反转。模型仍须在合法修订中保留任务所需信息；错误删改应记录为语义质量问题，不能宣称已经被程序普遍修复。

这不取消实际来源身份、当前路径、完整副本和工具关联的既有机械检查，也不把 `sourceRefs` 所表达的真实来源要求一起取消。

需要原文时，使用既有显式会话内读取入口，将结果返回到新尾部；不因此自动回填旧位置或建立新的尾部补偿流程。用户明确关闭清理时，沿用已接受的活动原文恢复和容量检查行为。原文在存储中存在，不等于当前模型已经启用读取工具；不能以一个引用冒充可用恢复能力。

普通请求保持已接受的稳定布局和前缀边界。滚动、有效指令变化、显式配置变化等有其现有行为与代价，不承诺 provider 必然命中缓存。新的前缀例外须明确改变了哪项行为，不能以“修复”为名直接引入。

## 5. 调用与资源边界

不新增独立压缩调度器、每轮记忆扫描、强制记忆工具调用或后台审查。正常维护复用当前模型的一次既有机会；既有 UI 清理至多一次的调用属于已接受入口，不因模型失败或没有减量而重试。

规划目标、显式硬限制、实际 API cap 和真实费用分别表达。启发式估算不冒充 tokenizer 证明；未知费用不按零处理。显式限制和实际准入继续生效，不能为发出请求而暗中丢弃用户输入或绕过容量检查。

失败保持明确，不追加 JSON 修补、模型切换、自动加倍额度或补救请求循环。宿主原生恢复按其现有边界处理，不扩大为普遍成功保证。

## 6. 非目标

当前不提供跨会话记忆库、主动历史检索、外部文档写入服务、通用知识图谱、事实真值数据库、永久语义依赖追踪或自动记忆纠错系统。

不接管业务任务管理、模型/凭据管理或 provider 传输；不要求安装其他 Agent 系统。为正确计量实际宿主请求而存在的可选兼容桥接，不授权选择身份、调度其他 Agent 或复制其状态。

这些是当前范围，不妨碍未来明确提出新产品需求；新需求必须如实说明兼容、资源和行为变化，不能从现有字段或测试反向推导出新承诺。

## 7. 证据与改动尺度

确定性的结构、预算、权限及状态行为以可执行检查验证。模型的语义判断以真实且有限的行为观察评估，不要求唯一工具顺序、固定措辞或每次同样结果。

关键事实漏存、错误完成判断等反例应报告和分析；结构通过或提示包含某些词句不证明语义质量。原始结果与失败记录保留其真实含义，修改产品范围后不能把删掉旧断言描述为已修好原问题。

验证覆盖实际改动，复用仍适用的证据。历史比较、完整验收库存和新版本回归各有消费者，过去运行过的矩阵不自动成为每次修改的要求。开发测试工具可以保留，但不据此增加生产能力、独立评估框架或强制重跑旧环境。

新增或删除机制都须对应当前问题，并比较收益、行为损失、资源成本和维护负担。简单的现有工具、直接命令或局部实现足够时，不增加独立系统。必要修正保持在实际受影响范围内。
