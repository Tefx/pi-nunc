# M 更新时的工具结果清理

## 1. 状态、目标与范围

**状态：用户已选择原模型完整方案，并要求先落文档、再由 Planner 创建实施计划；尚未实现。** 本文新增功能默认开启，可配置关闭。当前授权只覆盖文档和规划，不代表开始实现、安装、真实模型测试或部署。

目标：M 实际变化时，利用已经需要重建的请求后缀，清理已失去续做价值的工具正文，减少后续输入成本，同时保留任务要求、证据和恢复能力。完整交付包括机械清理、语义省略、局部摘要、逐项依赖验证、所有 M 修改入口、持久化、恢复、开关和观察。

不接 Jev；不增加普通轮次扫描、无变化 patch 清理或原生 compact 的新触发/替代流程。既有 Nunc 维护调用可携带清理决定，不改变 Pi 的压缩触发、队列或 transport 所有权。不新建调度器、数据库、清理服务、任务实体或通用依赖图。

本文是对 [DESIGN.md §2、§5.1](DESIGN.md) 中“保留历史原文不改写、不隐藏工具正文”的明确、有限修订：开启时允许本文定义的工具正文投影变换，其他消息和既有任务保留要求不变。本文不追认历史候选或运行效果。

调查依据：近期 11 个会话、4,238 条工具结果中，已测确定性内容去重约 2.36%，连同无损格式处理约 4.59%；40 条体积加权样本估计额外语义缩减潜力约 37.5%。单位是文本字符，非 token；无真实 M 修改时点或清理后续做验证，不能作为上线收益或准确率承诺。

## 2. 配置和关闭语义

沿用 Pi settings 的 `nunc` 区域，新增一个布尔项，不另加 CLI 开关或一套配置文件：

```json
{
  "nunc": {
    "toolResultCleanup": false
  }
}
```

- 缺省为 `true`；可信项目设置覆盖全局设置，再回落到默认值。未信任的项目设置不生效。非布尔值沿用现有 `CONFIG` 错误行为。
- 与 `memoryTools` 独立；不为了清理开启默认关闭的模型记忆工具。
- 关闭后：不生成清理候选、不进行新的机械或语义清理、不发起 UI 清理模型请求，现有 M 功能继续可用。
- 关闭时，活动路径上的既有清理决定不应用；后续请求恢复当前活动历史的原始工具正文。原始记录和清理记录都不删除，也不恢复已由历史滚动退出活动范围的消息。
- 恢复正文可能增加输入并改变缓存前缀，属于显式关闭的结果；先按真实恢复视图重新计量，超限沿用既有明确容量错误，不能为了发出请求而偷偷继续清理。
- 重新开启时，重新应用仍与当前路径/来源相符的已保存决定，不补跑过去漏掉的清理机会、不另发模型请求。
- 设置变化按现有设置读取生命周期生效。若实现支持会话中重新加载，必须使旧 usage/锚点失效，并取消或丢弃基于旧配置的未提交清理；不得跨开关状态提交过期结果。不要求新增热加载服务。
- UI 显示当前开关状态及当前是否应用已有清理，区分已保存的决定与当前有效投影。

## 3. 允许清理的位置与稳定性

以最近实际发出的主请求中可确认的旧 M 位置为准：

```text
旧请求：历史前段 | M旧 | 历史后段
新请求：历史前段 | 清理后的历史后段 | M新
```

“历史前段/后段”只描述缓存位置，不是压缩设计中的 B/K。

- 前段消息和顺序原样保留，机械去重/格式压缩也不能提前前缀变化位置。
- 仅把后段中继续进入下次主请求、已完成交付的工具结果作为候选；已经退出的历史不计入清理收益。
- 首次仅追加 M、旧 M/实际来源映射不可靠、无候选时跳过清理。不能通过移动锚点或扩张范围制造清理机会。
- 排除未完成调用组、本次 patch 所在调用组、最近一个完整业务工具调用组；不提前处理尚未交付的新输入。
- 不向历史正文插入标签或临时编号，复用已存在的来源引用。新增指令、候选表放在请求新增尾部或现有工具新返回结果中。
- 固定工具 schema/说明仅随功能配置和版本发生必要变化，不每轮动态重写 system、tools 或历史。当前 extraction 已使用独立 transcript，不承诺它与普通请求共享缓存；不为本功能重做传输层。
- 保存后的投影稳定复用，直到有效的新决定或显式开关改变；不反复恢复、再摘要同一段旧正文。已清理的结果不作为例行再次压缩候选。

布局和来源关联仍由 `src/pi/projection.ts` 拥有。清理后的正文不能导致现有锚点因文本不等而每轮漂移；实际请求、来源身份和清理投影必须能可靠对应，不能猜测其他扩展变换后的来源。前缀比较是本功能的可验证约束，provider 命中/费用仍以实际 usage 为准。

## 4. 判断机会和费用

| 入口 | 合同 |
|---|---|
| 既有 Nunc M 维护请求 | 复用当前模型、已有冻结来源和单次请求，同时生成 M 更新及清理决定；若最终 M 没变则不应用新清理。 |
| 模型 `nunc_memory_patch` | 复用已开启的记忆工具；`nunc_memory_read` 在新返回结果中提供候选引用和必要定位，不重复整份正文；主模型在同一次 patch 中给出清理决定。 |
| 用户 UI 修改 M | 确认修改后、提交前，在有语义候选时用当前模型作至多一次清理判断，冻结拟保存 M 和来源。界面显示“保存中”；用户取消整个保存时不提交。无候选则不调用。 |

UI 清理超时、模型/凭据不可用或清理响应失败时，仍保存合法用户修改，保留未经确认的正文，并明确说明清理未完成。模型失败不是记忆保存失败；底层保存失败仍按现有规则报告。等待期间会话、模型、路径或 revision 改变则拒绝过期提交，不自动重放用户修改。

开启意味着 UI 保存有上述额外调用成本；关闭后消除此成本。复用当前模型和现有请求预算、取消及 usage 观察，不增加模型选择器、备用模型或修复重试。只因清理没有减量而失败重试是不允许的。

若主模型拿不到某候选的完整正文，保留该项；可以使用已有原文读取入口有针对性恢复，但不能为了每次清理强制再读全部历史。

## 5. 内容处理标准

未列出的结果默认保留。保留调用参数、调用/结果关联、工具名、成功/失败状态和消息顺序，只改变获准的正文。

### 5.1 机械处理

在允许范围内，使用确定规则处理：

- 同源且正文完全一致的重复内容，保留一个完整副本；若依赖范围外的副本，则该副本也必须在下次请求中保留。
- 重复固定工具提示，保留必要的完整说明和所有动态句柄、状态、限制。
- 无损 JSON 格式和可逆目录结构紧凑表示、适用终端格式清理；不截断任意长行或去掉诊断数据。

默认保持工具输出未知格式；不得仅按工具名、年龄、成功状态或长度删除。具体支持的格式和私有解析方式由实现者选择，但不能宣称不完整的规则覆盖全部机械机会。机械保留副本也不能被同批语义清理删掉。

### 5.2 原模型语义判断

| 内容 | 可以退出或摘要的依据 | 必须保留 |
|---|---|---|
| 源码、diff | 当前消费已结束或被明确的新版本替代 | 后续编辑/比对需要的精确内容；保留版本、关键变化及恢复位置 |
| 搜索、目录、符号列表 | 定位已完成 | 选中的入口、尚未检查的范围、搜索限制 |
| 构建、测试、检查输出 | 可提取完整的结果和剩余问题 | 命令/目标、失败项、重要警告、数量和覆盖限制 |
| 错误/诊断日志 | 已解决，或可以无损保留仍需的诊断事实 | 独有现场证据、复现条件、未解决问题、非完整检查说明 |
| 结构化结果 | 可明确选择当前需要的字段/记录 | 有效子集、查询条件、截断/缺失和单位 |
| 要求、约束、验收标准 | 所有仍有效部分在最终可见内容中完整保留 | 数量、否定、适用范围、交互和完成条件，不得仅用路径替代 |

允许两种修改：`omit`（必要信息已被最终 M/其他保留消息覆盖，或确已失效）与 `replace`（在原位置保留简短、准确的续做记录）。摘要不得把推测写成事实、把局部成功写成全部完成、把“可重跑”当成历史状态已恢复。

未解决错误不一概禁止摘要，但其决定性证据必须可见。唯一且不可重建的观察不因已落日志就自动退役；当前是否需要直接看到由任务决定。图片、混合非文本和未知块保留，不增加视觉提取管线。未完整交付给本次模型的正文、含 `omissions` 的候选不允许据缺失内容做语义省略/摘要。

## 6. 公开接口扩展和校验

既有 maintenance 响应及 `nunc_memory_patch` 增加可选 `toolResultEdits`。既有 add/remove/priority/required 或 add/update/remove 的含义不变，缺字段等同不请求语义清理。

```ts
type ToolResultRef = { entryId: string; messageIndex: number };
type SourceRef = { entryId: string; messageIndex: number };
type ToolResultEdit = ToolResultRef & {
  action: "omit" | "replace";
  text?: string;          // replace 必填非空；omit 不携带摘要
  memoryRefs?: string[]; // 现有 slot ID 或同次新增 key
  sourceRefs?: SourceRef[];
};
```

这些是工具/响应边界的形状，不要求独立类或 registry。`messageIndex` 是当前来源 entry 投影内的零基消息序号。请求内现有 transcript 头部已提供 `entryId`、messages 和 toolCallId，不另注入 r1/r2。引用绑定冻结的当前 selected path/revision；toolCallId 只用于核对关联，不能单独作为全局身份。

`memoryRefs`/`sourceRefs` 指明该修改依赖哪些保留内容；若无外部依赖，replace 自身必须足以续做，omit 则只适用于确已失效的信息。此声明不证明语义正确，需行为验证。

- 先按现有预算和优先级得到最终 M，再逐项核验依赖是否保留。某项依赖被裁掉只撤销该项；其他合法清理继续。
- `sourceRefs` 必须指向最终完整保留的消息；互相依赖并同时退出的编辑不应用。用本批保留集合校验即可，不建立通用依赖图。
- 检查引用、范围、完成状态、配置、重复编辑、replace/omit 形状和预计净节省；不省空间的编辑保留原文。批内冲突项保留，不任意选一个版本。
- 清理部分无效时拒绝相应项，并在既有结果中附简短 applied/skipped 信息及原因；合法 M 更新不被可选清理阻塞。整个模型响应不可解析、M 部分无效等仍沿用原有错误合同。
- 记忆新增 key 到最终 slot ID 的映射由现有 patch 应用过程提供/使用，不增加另一套 ID。

`nunc_memory_read` 增加可选 `originals: ToolResultRef[]`，返回当前路径可解析的原始结果及错误/缺失说明；省略时保留原读记忆行为。候选列表仅含确切引用、工具名、来源定位和大小等必要字段，不附另一份工具正文。当前 revision 绑定读到的候选；并行分支变化后旧候选不能提交。

## 7. 状态、来源和一致性

原始 session 记录保持不变；本功能是请求投影，不是磁盘日志删除。M 和合法清理决定通过同一次现有提交生效，不允许正文先消失再保存记忆。取消、CAS 冲突、保存未确认时不启用新决定，保留现有恢复语义。

清理数据保存在现有 session 记忆记录/checkpoint details 的可选旁置字段，保持 `Memory/Slot` 原有含义，不把清理列表塞进模型记忆正文。**存储字段名、私有版本编码和内部类型是可替换实现选择**；约束是同提交、按路径恢复、旧记录兼容及不覆盖原始日志。

- `src/pi/manual.ts` 继续负责手工变更、revision、冻结和提交；清理不能绕过这些规则。
- `src/engine` 负责无副作用的候选/响应验证与预算，使用已有模型请求 seam；不直接读取 session 文件或写清理状态。
- `src/pi/projection.ts` 负责根据当前路径和开关应用清理、来源身份及稳定布局；Pi 层负责原文恢复。
- `src/pi/context.ts`、admission/accounting 和 UI 消费同一有效投影。快照同时能说明原始正文和当前替换，不把观察标成实际发送证据。

后续维护语义来源使用当前有效历史投影，携带清理标记和恢复引用，不例行把已隐藏原文重新塞回维护请求。需要原文时显式读取；新决定必须说明所依赖的是实际看见的内容。维护后只保留仍对后续活动范围有用的清理记录，不增加后台回收器。

摘要/省略标记由代码统一添加，明确这是 Nunc 缩减表示并附来源引用；模型不伪造原始工具结果。恢复读取产生新的尾部工具结果，不重新展开旧位置。恢复来源限定本会话选定路径，不把调用工具重跑当作历史原文。

## 8. 兼容与失败

- 旧 session 无清理字段时照常读取；不要求迁移或重写历史。关闭时投影恢复原文，不写回反向迁移。
- 卸载/旧版本无法应用清理时，可恢复到原始活动历史；不承诺这时仍维持清理后的输入大小。已有手工 M 卸载限制不变。
- 开启状态下已保存的有效清理决定不因进程重启而丢失；新清理机会的旧主请求锚点未知时仍跳过，不猜缓存前缀。
- 已保存决定无法对应原始条目或来源不符时，该项不应用并披露；来源确实不可用时明确缺失，不能编造原文。
- UI 清理失败、optional 编辑非法和无净收益均不触发另一次模型调用。实际容量失败继续由现有 admission 路径处理。
- 不以清理为理由改变任务范围、丢掉有效要求或放宽原有 M 保真验收。

## 9. 验收与实施边界

实现、文档和测试需同时覆盖：

1. 默认开启、显式关闭、可信项目/全局优先级、非法值、开关恢复正文、重新开启和独立的 memoryTools 设置。关闭时确认没有清理候选/变换/额外请求。
2. 主请求前段字节/结构不变，候选和恢复只追加到新尾部；已清理消息仍能稳定锚定，不因自有变换每轮漂移。原模型请求和实际 usage 的证据分开。
3. 机械规则保留全部有效值、动态句柄和完整副本；无跨退休历史的假重复。
4. omit/replace、完整来源限制、任务义务与错误事实保留、最终 slot/source 依赖、非法/重复/互相依赖项的局部拒绝。
5. 原有维护、模型 patch、UI 保存均可完成完整功能；无变化、取消、超时、无凭据、过期 revision、配置变化和保存未确认不误删、不重放。
6. 原文读取、恢复/分支切换、旧记录、关闭/卸载、预算/UI/实际请求一致，以及清理状态随历史退出的有界性。
7. 真实 M 更新时点的对照续做：原始不清理 vs 原模型完整清理，比较完成质量、遗漏、恢复次数、实际输入/cache usage、总成本和端到端等待时间。包含中文要求、修复未完成、摘要数量/否定、部分测试成功和源文件已变化；不向被测模型提供预期清理答案。

机械检查不能替代原模型行为证据，字符减量不等于费用收益。复用已有测试/runner 和现场证据；只有当前接口无法表达必要观察时才做局部扩展，不新增独立评估框架。真实模型调用、安装和持久外部效果须在实施授权及明确的环境/费用边界下进行，本次文档/规划不执行这些动作。

Planner 根据当前仓库安排可独立验收的结果和集成责任，保持已完成 Plan 历史不变。不要以文件、格式化或逐条测试拆步骤，也不要为此补建 architecture_basis 或额外治理实体。
