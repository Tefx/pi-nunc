# 稳定记忆位置与滚动历史保留比例

状态：**稳定布局与观察支持已实施**。更新于 2026-09-13。默认保留比例 `rolling.keepRecentFraction: 0.5` 已在 `src/pi/config.ts` 实施；主请求在内容不变时使用进程内稳定锚点 `F | R前 | M | R后`。真实模型缓存/任务质量仍由下游 `verify-live` 消费者按 m1–m4 观察入口执行。

以下布局合同取代旧文档的“每次请求必须尾置 M”；CRUD、CAS、持久化、预算、Larva v1 与 Pi 所有权等未被修改的合同继续适用。

最新测试约束：**实际模型测试优先 Gemini，可以有限使用 GPT Luna，禁止使用 Astra**。该约束覆盖主请求、维护请求和模型观察者；旧方案中补做 Astra 更新转换测试的要求已撤回，历史 Astra 证据仍可引用。

## 1. 目标与修改判断

保留滚动上下文、持久记忆、正常 memory patch 能力，同时：

1. 消除记忆内容未变、位置却随每轮请求移动造成的缓存损失。
2. 增加每次压缩释放的空间，降低残留上下文大小和压缩频率。
3. 保持真实历史、工具关联、CAS 并发保护、容量保护和 Pi 原生调度。

固定记忆位置应当实施；默认保留比例采用 `0.5`，实际收益仍需集成验证。`0.5` 是已选择的工程折中值，尚未证明最优。

`src/pi/projection.ts::withEffectiveMemory()` 在内容不变且路径/边界仍合法时复用进程内锚点；普通历史追加不移动 M。首次构造或内容更新在当前请求的合法尾边界建立锚点。

已有实验支持布局修正：

| 观察 | 结果与范围 |
| --- | --- |
| 实际 Astra session，正常注入 | 输入 236,686，缓存 20,992；观察到的历史缓存为 0 |
| 同一 session 临时仅省略最终 M | 首轮仍冷，后两轮命中率 99.71% 与 99.76%；未删除真实历史或持久记忆 |
| 较大 M 持续移到尾部，对照同样 M 固定位置 | 移动布局连续三轮缓存为 0；固定布局恢复高命中 |
| Astra/xhigh/SSE，约 17k 输入，固定 M | 缓存 `0 → 17,024 → 17,024` |
| Luna/SSE，约 146k 输入，第 4 轮更新并重新定位 M | 缓存 `0 → 146,176 → 146,176 → 0 → 146,176 → 146,176` |
| 移动 M 的末尾增加每轮变化标记 | 未改善缓存 |
| Codex 路径的 Luna、Astra，marker-only 请求 | 均拒绝 `prompt_cache_breakpoint` |

这些结果不证明私有后端的完整查找算法，不保证 patch 后只冷一轮，不保证恢复注入后持续命中，也没有验证完整扩展环境中的任务质量。历史模型名称只标识已有证据，不授权新的 Astra 调用。

## 2. 请求布局

### 2.1 同一份有效记忆保持固定位置

当前布局：

```text
第1轮：F | R1 | M
第2轮：F | R1 | 新增历史1 | M
第3轮：F | R1 | 新增历史1 | 新增历史2 | M
```

目标布局：

```text
第1轮：F | R1 | M1
第2轮：F | R1 | M1 | 新增历史1
第3轮：F | R1 | M1 | 新增历史1 | 新增历史2
```

统一表达为：

```text
F | R前 | M | R后
R = R前 + R后
```

R前/R后仅描述 M 两侧已经交付的真实历史，无须建立第二份历史存储。现有 UI 的 D 继续表示尚未交付的队列输入；交付后属于 R，不用 D 表示 M 后的全部消息。

要求：

- 非空 M 每个请求恰好一份；空 M 不注入载体。
- 普通历史追加不移动 M。
- 保持发送内容和相对历史边界稳定，无须永久复用同一个 JavaScript 对象。
- 保持当前 user-role、reference-only 语义，不升级为 system/developer 指令，不伪装成新的用户任务。
- 请求载体不追加到会话，不产生额外 agent turn，不嵌入时间、随机数或 CAS revision。

### 2.2 内容更新后替换并重新定位

假设新增历史3包含一次 memory patch 调用及完整工具结果：

```text
更新前：F | R1 | M1 | 新增历史1 | 新增历史2
更新后：F | R1 | 新增历史1 | 新增历史2 | 新增历史3 | M2
后续：  F | R1 | 新增历史1 | 新增历史2 | 新增历史3 | M2 | 新增历史4
```

新位置在首次构造使用新内容的请求时，选取该请求的合法尾边界建立，之后保持稳定。所谓“尾边界”只用于建立新锚点，不在后续每次请求重新选择。

只移除旧请求载体，不删除或改写真实历史、持久记忆记录。已构造的在途请求保留其发送时的 M 和位置快照；随后构造的请求使用新内容。UI 读取不能建立或推进请求锚点。

## 3. revision、内容与位置必须分离

当前 CAS revision 包含：

```text
sessionId + checkpointId + manualMemoryHead + leafId
```

普通历史增长会改变 `leafId`。**完整 CAS revision 不得充当记忆内容版本或布局失效条件。**

| 判断 | 依据 | 职责 |
| --- | --- | --- |
| 内容变化 | 实际发送的 `renderMemory(slots)` | 判断是否替换 M |
| 位置有效性 | 当前选中路径、可见历史、锚点存续、合法消息边界 | 判断是否重新定位 |
| 写入冲突 | 原有 `memoryRevision()`、`revisionApplies()` | 判断是否允许提交 |

比较实际发送内容，包含 slot ID、顺序和正文，不做语义相似度判断。`nextId`、manual head 或完整 revision 变化，不直接意味着发送内容变化。普通历史追加不能自动使锚点失效；检查点变化需要重新验证位置，不能直接等同于内容变化。

无内容变化的 patch 仍必须先通过 CAS 校验，不能用“内容相同”绕过冲突。保留现有 revision 格式和语义，包括允许符合条件的同路径祖先 leaf revision 继续适用；过期记忆头、跨分支和其他原有冲突继续按原规则处理。无效、冲突、取消或没有实际内容变化的更新不能无意义地重新定位。

## 4. 锚点所有权与生命周期

### 4.1 所有权

锚点由 Pi projection adapter 独占管理。持久有效记忆仍来自当前选中路径的原生 checkpoint 和适用的 manual memory 记录；Admission 消费已构造的请求快照，UI 消费只读位置及内容信息，Engine 不拥有 session 锚点状态。

推荐使用进程内锚点状态，不新增持久化存储、迁移 entry 或跨 session registry。具体内部类型、字段和数据结构可替换，只要满足请求边界和状态所有权。

### 4.2 路径、压缩与恢复

分支切换、压缩或恢复时检查：

1. 是否属于当前 session 和选中路径。
2. 锚点对应的真实历史是否仍可见。
3. 原插入边界是否仍合法。
4. 有效记忆发送内容是否变化。

仍有效则保留；失效或恢复后没有可用锚点则重新建立合法位置。普通历史追加不能自动触发失效。重新建立可能需要缓存预热，不承诺跨重启保持热缓存。

Pi 的 `buildContextEntries()` 将最新 compaction 放在返回数组开头，不能把该数组下标直接当作历史时间位置。来源/路径验证使用正确的原生选中路径语义，不通过退役历史正文或外部日志补造当前请求。

### 4.3 实际 hook 输入映射与失败行为

Pi 的 `emitContext()` 会先执行 `structuredClone(messages)`，不能用 session 消息与 hook 消息的跨请求对象身份相等定位锚点。

实现必须验证选中历史边界与实际 hook 输入之间的对应关系：保留其他扩展已经提供的消息及变换，不从 session entries 重建整份请求来覆盖 hook 输入，不靠重复文本猜测边界。

无法恢复旧位置时，使用明确的合法重建规则。无法确认合法工具关联时沿现有错误路径处理，不通过丢弃 M、真实历史或工具结果继续。不将仅缺少 receipt 来源关联当作消息非法；该情况仍可对实际完整 Context 重新估算。恢复、容量拒绝及取消继续由各自现有 owner 处理。


当前实现只复用能够与选中路径中的完整原生消息单元建立唯一对应的插入边界。未映射、部分映射或重复内容导致边界歧义时，在实际 hook 输入的合法尾边界重建，保留所有扩展消息；空来源 ID 集合不能证明路径有效。压缩退役较早前缀后，只要实际边界仍存在且对应关系有效，M 仍跟随该边界，绝对下标可以减小。无来源对应的 UI 位置显示未知。

## 5. 工具调用边界

M 不能插入 assistant 工具调用与对应结果之间。不能只在插入后调用 `legalCuts()` 就认为安全；当前校验可能接受这种最终关联完整的序列：

```text
assistant(toolCall) | user(M) | toolResult
```

Pi 的 `transform-messages.js` 会将中间 user 消息视为工具流程中断，并可能补出 `No result provided`。

因此必须从真实历史先确定没有未完成工具调用的边界，再插入 M。多个并行调用必须等待全部对应结果，不能只等待 memory patch 自己的结果。memory patch 的持久记录位置不能直接当作插入位置，提交时其工具结果可能尚未完成。

验收检查实际序列化结果：调用/结果一一对应、完整保留，没有因 M 插入而产生的合成缺失结果，不能仅检查内部关联表。

## 6. 统一布局消费者

请求投影向下游提供同一份请求局部快照：实际消息序列、当前有效 M、M 在转换后消息中的明确位置（空 M 无位置），以及排除该载体后的全部真实历史 R。显式可空位置索引是可用的内部表示，不固定其名称或私有类型。

载体识别继续依赖投影来源关联，不通过搜索正文中的 Nunc 字样识别。保留载体来源和独立内容快照校验，以识别后续 hook 对同一对象的内容修改。

| 模块 | 修改范围 |
| --- | --- |
| `src/pi/projection.ts` | 稳定锚点、内容判断、载体替换、合法位置、路径验证 |
| `src/index.ts` | 同一请求的投影、绑定与委托使用同一快照；注册补充后的 patch 工具提示 |
| `src/pi/admission.ts` | 移除 `.at(-1)`、`slice(0,-1)` 等尾部假设；保持来源、模型、signal、一次性调用及内容绑定 |
| `src/pi/context.ts` | 不再用前 `rCount` 条代表 R，避免计入中段 M、漏掉尾部真实历史 |
| `src/ui/context-tree.ts` 等 UI 消费者 | 显示实际插入位置；保持 Current、Last main、Last maintenance 范围分离 |
| `src/engine/accounting.ts` | 保证全部 R 与一份 M 的一致计量；需要有序上下文的消费者使用有效位置 |
| 文档及相关测试 | 更新“记忆始终尾置”的旧合同 |

UI 可以继续使用 F/R/M 分类，但必须说明分类与实际请求顺序的区别。Current 只说明当前投影，不声称包含之后运行的 hook；Last main 使用该次请求的 M/位置快照，不在完成时重读当前 M。无法识别位置时明确显示未知，不猜测尾部。

## 7. 预算与 usage receipt

### 7.1 全部真实历史都计入预算

`R = R前 + R后`。重新定位 M 只改变相对位置，不减少真实输入，不重置历史预算。

当前 `requestTokens()` 按消息求和，位置变化本身不改变估算总量。Engine 无须为位置管理引入 session 生命周期依赖。主请求的有序构造、预算和 UI 必须对同一有效内容一致计量，不能同时计入旧载体，也不能只统计 M 后的历史。

Maintenance 继续使用原有 M/B/K 提取协议，不把主请求载体布局机械搬入维护提示。

### 7.2 保留既有保守 receipt 公式

本次不调整原有容量保护语义：

```text
usage-backed 估算
= 旧请求及响应的实测 U
+ 响应锚点之后的新增真实历史估算
+ 当前完整 M 估算
+ 原有配置及 metadata 额外计量
```

U 为旧 input（含 cacheRead/cacheWrite）加旧 output；reasoning 已包含在 output 中。U 内保留旧 M 的实际贡献，不扣除启发式估算的旧 M；不重复添加 F，不重复估算已计入 U 的响应，不把上次 Nunc 估算递归当成新 U。空 M 的当前载体项为零。

无有效请求关联时，重新估算实际完整 Context。保留模型、有效 F、tools、真实历史前缀、成功响应和 payload 绑定校验。保留在途请求发送时的 M 快照，不能在完成时重读新 M。单纯 M 更新不无条件清空仍适用的 receipt；路径、配置等变化继续按原适用规则处理。

服务端缓存命中与本地 usage receipt 复用分别验证。所有估算仍是 planning heuristic，不是 provider tokenizer 的硬上界。**不修改 Pi 的 `previous_response_id` 输入一致性检查**，也不抬高容量上限或改变输出/维护/取消保护来隐藏估算问题。

## 8. 滚动窗口保留比例

默认值由 `rolling.keepRecentFraction: 0.67` 改为 `0.5`，继续使用现有公式：

```text
保留真实历史目标
= floor(keepRecentFraction × (available − memoryLimit))
```

| available | memoryLimit | 比例 | 保留目标 |
| ---: | ---: | ---: | ---: |
| 220,000 | 22,000 | 0.67 | 132,660 |
| 220,000 | 22,000 | 0.5 | 99,000 |

同预算下目标降低约 25.4%。`0.5` 是已选择的工程折中值，尚未证明最优。

不修改压缩触发阈值，不新增调度器。保留显式配置覆盖，不改写用户配置。继续保留合法完整消息单元；没有完整单元低于目标时，采用现有最小可行超目标后缀规则。相同比例差异不保证每次产生不同切点。

历史中五次 Nunc 压缩后的首个请求分别为 156,501、160,877、177,544、209,539、220,187 输入 tokens；它们发生于不同时间/输入，缺少受控配置对照，不能全部归因于默认比例。用实际 provider usage 验证压缩结果，不把启发式目标、日志 tokensBefore 和实测输入混作精确同一口径。触发阈值不变也意味着后续上下文仍可能增长到原高水位。

## 9. memory patch 工具提示

在现有保存内容、权限、CAS 和恢复提示基础上补充：

> 仅在需要持久保留的信息发生实质变化时更新记忆。合并当前已经确定、可一起提交的修改，避免重复写入、无意义改写，以及为记录每一步执行过程而频繁更新。记忆变更可能使后续请求重新建立缓存；不要因此延迟必要的信息保存、错误纠正或过期内容删除。记忆位置由 Nunc 管理，无须手动删除并重新插入记忆。

不设置固定调用频率、冷却时间或每轮配额。现有最近 100 次请求样本只有 3 次紧随有效记忆变化，不能据此要求大幅降低 patch 频率。提示说明保存取舍，不承诺缓存收益，不授予笔记指令权限。

## 10. 兼容与非目标

- 保留现有 Memory/Slot 持久格式、slot ID、顺序、nextId 及 CAS 合同。
- 不为调整载体位置重写 JSONL 或追加迁移记录；旧 checkpoint 生成的 summary carrier 仍需每次幂等规范化。
- 不删除真实历史中的旧 memory read/patch 调用及结果。
- 不新增显式缓存标记；当前测试的 Codex Luna、Astra 路径均拒绝该标记。
- 不新增生产环境双布局开关；移动布局仅作为对照实验基线，不成为正常运行回退模式。
- 不改变 Pi 的认证、传输、工具执行、队列、压缩触发和重试所有权。
- 同步更新 README、[PI.md](PI.md)、[UI.md](UI.md)、[ACTIVE-MEMORY.md](ACTIVE-MEMORY.md) 及受影响的实现/验证说明，区分已实现行为与待实施设计。

## 11. 验收与模型测试边界

### 11.1 布局、revision 与状态

至少覆盖：

- 普通历史追加使完整 revision 改变，但 M 的发送内容和相对历史边界不变。
- 无实际内容变化的 patch 不重新定位；无效、冲突、取消的 patch 不改变有效布局。
- 无内容变化的 patch 也执行原 CAS 检查，不能绕过过期或跨分支冲突。
- 内容更新后旧载体消失，新载体唯一，后续位置稳定；空→非空、非空→空转换正确。
- 分支切换、压缩使锚点失效时合法重建；仍有效时保持。恢复缺失锚点按明确规则重建。
- 原 CAS 允许的祖先 leaf 写入继续允许，过期记忆头和跨分支冲突继续拒绝。
- 在途请求旧快照与随后请求新快照正确分离。
- 克隆、转换及其他扩展 hook 不导致误识别、错误沿用 receipt 或真实消息丢失。
- 并行工具组完整，没有因 M 插入而合成的缺失结果。
- Admission、receipt、预算、UI 均正确处理中段 M；外观类似记忆的真实 user 消息仍属于 R。
- 从真实 loader/context hook 到原生 serializer 的序列中，唯一 M、实际位置、真实历史及工具关联均符合合同；不松动 `previous_response_id` 检查。

现有断言尾置的测试应随新合同改为稳定位置和真实序列化行为检查；不能只改期望输出掩盖内容或状态错误。相关离线测试、完整库存和实际 Larva 组合证据按 [DEVELOPMENT.md](DEVELOPMENT.md) 的入口与适用性要求取得。

### 11.2 缓存与记忆使用效果

对照移动 M 和固定 M，记录实际输入量、缓存量、模型、effort、transport、有效配置和阶段。检查实际序列化请求中的唯一 M、内容和位置。分别报告热缓存、patch 后重建、压缩、长时间停顿和配置变化，不承诺无条件命中率。

使用只有 M 提供必要信息的任务，检查更新、纠错、删除后的实际行动或产物。不把期望答案直接交给被测模型。已有 ACK 实验仅证明缓存现象，不计为记忆使用质量验证。使用完整扩展环境，不能以直接导入 projection 的隔离探针替代。
