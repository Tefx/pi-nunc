# Stock Pi extension

Target: **Pi/pi-ai 0.85.1**, persistent sessions. Nunc is an independent public extension. Stock Pi owns its CLI/TUI/RPC, compaction lifecycle, scheduling, retry, JSONL writes and context rebuilding. The extension requires no SDK host, replacement launcher, private patch, another extension or global installation.

The original core and subsequent native/cooperative compatibility acceptance are complete in the managed plan. The UI in [UI.md](UI.md) is accepted design, not current functionality; later capacity/command changes and this document do not retroactively extend historical evidence.

## Load and configure

Build with the locked local tools (`npm run build`), then choose the extension explicitly for one Pi invocation:

```sh
/opt/homebrew/bin/node /absolute/pi-nunc/node_modules/@earendil-works/pi-coding-agent/dist/cli.js \
  -e /absolute/pi-nunc/dist/src/index.js --nunc-config /absolute/nunc.json
```

`package.json` also declares `pi.extensions`. Omit the flag for Nunc defaults. Relative configuration paths resolve from Pi's cwd; `policyFile` resolves from the configuration file's directory. Nunc reads these files without writing them. `/nunc` shows a three-line memory count and compaction-trigger summary without making a request. `/nunc details` adds grouped input/output budgets, the maintenance cap and latest maintenance observations; numeric budgets use thousands separators. Both commands leave the transcript unchanged. The native argument completion menu suggests `details` after `/nunc ` or a matching prefix such as `/nunc d`. Remove the extension resource and use stock `/reload`, or start without it, to unload. Existing summaries remain readable by stock Pi.

**Planned command compatibility:** the UI feature will make bare `/nunc` open the Slots/Context overlay only in TUI. Other modes retain the text summary. New `/nunc status` explicitly selects the text summary; `/nunc details`, its existing grouped observations, thousands separators and argument completion remain available. `status` joins the completion menu. No read-only command starts a model request, compaction or session write. These changes are not implemented yet.

```json
{
  "policyFile": "./preferences.md",
  "memory": { "fraction": 0.1, "maxTokens": 2000 },
  "rolling": { "keepRecentFraction": 0.67 },
  "extraction": { "toolResults": "auto", "headTailChars": 200, "outputTokens": 8192 },
  "budget": { "safetyTokens": 1024, "growthTokens": 1024 }
}
```

All fields are optional. Unknown fields/types fail explicitly. Memory fraction is `[0,1)`, kept fraction is `(0,1)`; integer bounds are positive. Optional `budget.extraMainInputTokens`, `extraExtractionInputTokens`, `inputLimit` and `imageTokens` express justified provider framing/input/media bounds; extra inputs may be zero. `policyFile` supplies UTF-8 supplemental preferences. Whole-slot, reference, terminal-response and capacity checks always apply.

Pi's effective `compaction.reserveTokens` sets `H = model.contextWindow - reserveTokens`. Require positive reserve/H and `0 <= keepRecentTokens < H`. Pi's `keepRecentTokens` affects native preparation; Nunc independently chooses a legal suffix using its retained fraction. A nonempty retiring prefix and legal retained unit are still necessary. The controlled fixture's window 60,000/reserve 36,000/initial keep 1 gives H=24,000; these numbers are mechanics fixtures, not general recommendations. Measure the selected model's full extraction overhead and trigger earlier when needed.

The extension inherits `ctx.model`, current thinking and actual native request options, so startup/runtime model selection takes precedence over static saved defaults. No authentication setup command is part of Nunc. Verification isolates task sessions/files and records only nonsecret effective metadata; named test overrides stay invocation-local. Standalone runner startup resolves its own defaults; preserving another runtime's unsaved selection requires explicit nonsecret forwarding from that runtime's public context.

Stock settings are read through public `SettingsManager.create(cwd, getAgentDir(), {projectTrusted: ctx.isProjectTrusted()})`; declined project settings remain excluded. Component fixtures may supply the exported read-only `bindHostSettings` callback on their loader event bus. The supported stock route needs no callback. A disagreement with actual native preparation cancels maintenance.

## Delivered source and native handoff

At `session_before_compact`, Nunc freezes the selected, already-delivered `R = B | K` plus existing M and effective system/tools F. Public `buildContextEntries()` → `sessionEntryToContextMessages()` → `convertToLlm()` supplies evidence. Nunc does not inspect Pi's pending queues, reconstruct inputs, consume future D, or open retired history/log references. A pre-prompt threshold can therefore run before the new prompt is delivered. Pi appends that original prompt afterward; actual request admission checks it then.

Full visible tool bodies, arguments, associations, errors, custom messages, bash results and branch summaries remain source. Excluded bash and plain custom state are absent. Failed/aborted assistant output is excluded consistently with native request/overflow handling. Every compaction entry is a summary carrier and is excluded from R. Current memory is decoded once from the newest checkpoint.

Legal real K entries may precede earlier checkpoint entries. Nunc retains those entries unchanged and excludes every obsolete summary carrier from extraction and ordinary context. It does not move the boundary past the newest checkpoint merely to avoid old summaries. The ordinary context hook keeps exactly the newest native summary, without rewriting real K. Later extensions may add or filter their own outbound messages. Maintenance still reads the selected path through `buildContextEntries()`, not the last outbound Context: temporary injections are not a memory source, and already-saved text that a later hook hides can still be extracted. Temporary filtering is not an exclusion from memory. Nunc does not scan converted user text, hash slots, or add hidden marks to recognize M.

`auto` extraction uses complete F/M/B/K first. Only measured capacity overshoot permits one explicit, marked tool-body reduction; `full` prohibits reduction. Neither mode alters Pi's original retained K. Images require advertised support and a justified per-image upper bound. Unknown/audio/PDF blocks and invalid tool associations fail explicitly.

The engine produces one complete candidate. Nunc checks cancellation, session/file/leaf/generation, selected model/thinking, effective F, settings and configuration before handoff. Model/session/path changes abort in-flight extraction. Policy text freezes for one transaction; edits apply on the next. Preparation, policy, extraction and validation failures return `{cancel:true}` and cannot fall through to the default summarizer.

Pi receives one native `CompactionEntry` result: `summary`, `firstKeptEntryId`, `tokensBefore`, and `details.nunc = {version:1,slots,nextId}`. The current maintenance implementation writes no entries itself and has no second memory store. The accepted UI design adds M-only manual revisions via public `pi.appendEntry()` (see below); the native maintenance checkpoint remains the sole owner of the retained-history boundary. Pi owns later append/rebuild failures; its in-memory state may advance before a failed file append. Reconcile native session/file state before retrying a failed write. Nunc supplies no rollback or replay.

## Planned manual memory revisions

[UI.md §5](UI.md#5-人工记忆提交与兼容) defines the accepted extension to persistence. The adapter will project effective M from the selected path's latest native checkpoint and applicable subsequent manual revisions. A public native CustomEntry is the recommended carrier; no second K store, old JSONL edits, replay or host patch is introduced. The main context carries effective M once; real K stays unchanged. Subsequent maintenance freezes effective M and absorbs the result into the next native CompactionEntry, without reapplying older revisions.

Manual saving affects requests constructed after successful save, not already constructed/in-flight requests. Saving and the maintenance freeze-through-native-terminal window exclude one another, without locking an entire agent run. Revision conflicts and validation failures retain drafts; a native append error is an unconfirmed save, not proof of unchanged in-memory state or permission to retry automatically. The inspector uses current accounting semantics and reports observation limits; it does not change Provider or payload delegation.

**Unload/downgrade limitation:** manual changes not yet folded into a native compaction require the new Nunc implementation. Stock Pi or an older Nunc reads the last native summary. Existing sessions need no rewrite. `ctx.compact()` is unsuitable as an every-edit save operation: in Pi 0.85.1 it first aborts and may reject preparation before the extension hook.

## Main-request admission

Nunc captures the current public native Provider through ModelRegistry.getProvider, wraps stream/streamSimple, and delegates transport. Verified Completions, Responses, Azure Responses and Anthropic routes, plus uncapped Codex/Responses routes, use min(model.maxTokens, compaction.reserveTokens) as main input planning headroom, covering the serializer floor. Main output/thinking stay native. Other routes retain fixed-reserve accounting until context sizing is verified. Main estimation uses applicable Pi usage plus trailing input only while the model, system/tools and delivered prefix match the preceding delegated request; otherwise it freshly estimates text/schema/framing/media. Lifecycle and payload changes invalidate that attribution. There is no worst-case joint input-plus-maximum-output guarantee. For the 272000/128000 Codex catalog with Pi reserve 16384 and safety 1024, planned main input is 254592. Extraction defaults to an independent 8192 planning reserve, yielding planned input 262784. Codex sends no output cap. Capped extraction sends the configured ceiling; uncapped complete responses may exceed the planning reserve while remaining within actual model/provider limits. Billing/call authorization still uses full native output capability. Legacy explicit extraction.outputTokens equal to model.maxTokens is honored with a migration warning; remove that override to select the new default. Nunc never rewrites saved settings.

The wrapper classifies each call. Nunc-owned maintenance uses a one-shot `AsyncLocalStorage` binding to the engine's exact context, model, signal and output ceiling; a repeat or binding change of that same context cannot escape as an independent call. Stock `streamSimple` with the current session id and the current nonempty run signal is the main-session scope: Nunc then checks model identity and the **actual final** Context, including F/tools, media, metadata and configured framing bounds, before original transport dispatch. Other independent calls are delegated unchanged and do not consume Nunc main-session rules or maintenance budget. Prompt text, empty tools or matching model IDs never establish maintenance identity. Session/signal/model fields describe scope, not unique caller identity; a helper `streamSimple` that reuses the same session and run signal is admitted as main.

An oversized, owned main request produces a local capacity error recognized by Pi's native overflow logic. The rejection makes no HTTP request. Pi alone decides whether to compact and retry. With auto-compaction disabled it stays disabled; explicit `/compact`, smaller input or a larger supported model remains available. Indivisible input or a request without a legal retiring prefix fails without a recovery loop. Nunc never calls `ctx.abort`, initiates compaction from the context hook, withdraws queues or resubmits a prompt.

Actual user cancellation takes precedence over owned capacity errors. Stock TUI also flushes its compaction queue after Escape. When the native automatic-maintenance signal is aborted, Nunc rejects resulting main transports until that run settles. Pi still owns queue delivery, persistence and editor behavior; Nunc does not restore or remove queued text. A new explicit request after settlement can continue normally.

Public `before_provider_request` handlers run in extension load order. Returning `undefined` keeps the current object (observe-only or in-place). Any other return replaces the payload for later handlers and for the request. Stock `createAgentSession` always forwards that composed result through native `onPayload`. Nunc compares JSON-enumerable bytes, not prototypes or object identity: no-op and identity returns may proceed. Proven-safe sampling/container keys (`temperature`, `top_p`/`topP`, `top_k`/`topK`, `presence_penalty`, `frequency_penalty`, `seed`, `user`, `metadata`) may change in place or by replacement when remaining input allows. Unchanged unknown APIs still delegate. Any other changed field is an unrecognized modification and fails before HTTP; Nunc does not treat unknown keys as safe metadata. A last-user text append that only adds nonempty `input_text`/`text` suffix parts on the last `role: user` message (wrapping a nonempty string first, keeping every earlier message, prefix block, tool association, media part, and control field) is accounted as input growth. Multiple public hooks may each append; Nunc sums added text and JSON framing and does not net shrinkage against other fields. Added bytes are checked against Nunc remaining input independently. When a serialized cap is present, remaining native room uses Pi's `estimateContextTokens` (messages, tools, usage) plus estimated append overhead against `contextWindow` and the clamped cap, not the whole Nunc byte estimate. The callback does not lower the native cap. Completions `n` and Google serializer `config.maxOutputTokens` / `config.systemInstruction` / `config.tools` / `config.thinkingConfig` are control or input/tools/thinking fields, not metadata. Other input/tools/media/thinking/control rewrites are unvalidated without a provider mapper and fail before HTTP. Output caps cannot expand past the native serialized ceiling, change cap field path (for example Responses `max_output_tokens` to Completions `max_tokens` at the same number), be omitted when one was present, invent a cap on an uncapped API, or use invalid/conflicting fields. A native `stream: true` or `model` key cannot be deleted or retyped; APIs that never serialized `stream` are not required to grow one. Non-streaming/background payloads, selected-model changes, unsupported media, and metadata growth that exceeds remaining input fail before HTTP with a field-category diagnostic. Main-session payload `CAPACITY` errors use the owned `context_length_exceeded` prefix and cancellation map so native overflow recovery still recognizes them. Independent calls keep the original `onPayload`. A later public provider registration is captured on the next context; a transparent wrap of the current Provider between settled calls is re-captured so Nunc stays the entry wrapper. The first Nunc wrapper on a delegated call admits once. An inner Nunc wrapper is passed through only on its first visit of that same Context/model/signal/stream-vs-simple call; a second visit, including from a nested native callback, enters again. A held or prepare-captured older wrapper that is not that in-flight call still runs registered, source, capacity and maintenance guards. Native `prepareRequest` can capture a provider before `transformHeaders`/auth await; a wrap during that await does not skip admission. After teardown, leftover wrappers in a closed chain stay transparent. Independent nested calls with a different Context or signal do not inherit the in-flight ticket. Maintenance uses public `ModelRegistry.complete`: native Provider/auth headers apply on main and maintenance; SDK-only `before_provider_headers`, `before_provider_request`, and `after_provider_response` hooks do not. Put headers required on extraction on public Provider/auth configuration. The extension does not replace host authentication. Codex OAuth, refresh, request compression and transport remain native. Its subscription cost placeholders do not establish USD billing; Nunc maintenance observations report billing as unknown. The bounded runner uses the native SSE path and full output reservations, without adding `max_output_tokens`. The live observer registers an observe-only handler plus an identity return so three-route runs compose callbacks; it logs field names only. Named override `payload-append` adds `-e dist/src/live/append.js`, which appends the tracked synthetic last-user string through the same public callback. Diagnostics report mode, categories, and optional `transform: last-user-text-append` without bodies, headers, credentials or paths.

## Supported boundary and evidence

- Persistent stock Pi **0.85.1** only; `--no-session` is unsupported. No minimum-version/all-provider claim.
- Admission captures the registered native `Provider` and delegates `stream`/`streamSimple`. It does not maintain an API-name allowlist or a per-extension rewrite mapper. Last-user text append is a shape check on `input`/`messages`, not a provider or extension name. Unchanged unknown APIs still delegate. Live observer transport binds HTTP to the authorized `model.baseUrl` origin and path prefix, requires POST/SSE/single-send/no-retry/no-redirect, and checks the actual serialized output cap when present (otherwise the full `model.maxTokens` reservation). A missing `baseUrl` fails as a missing destination field. Google Generative AI's public adapter rejects custom `fetch`, so the observer cannot intercept that adapter's HTTP; admission still delegates it and classifies that serializer's `config` fields. Codex OAuth remains a native route when that model is selected.
- One custom compaction owner. Pi runs every owner and keeps the last result; `cancel` stops later handlers. Nunc does not disable other extensions by name or edit their settings. If another owner is also enabled, configure exactly one writer. Legacy stream overrides, raw sampling payload overrides, constrained tool sampling (absent from public maintenance `ToolInfo`), per-main-call `maxTokens` overrides on the main-session path, and a prepared entry wrapper that is no longer the registered native are unsupported. Main/maintenance payload callbacks may observe, return, or mutate in place. Proven sampling/container metadata that stays within remaining input may send. Last-user text append that preserves prefix messages/blocks/tools/media/control may send after capacity accounting. Unrecognized field changes, unvalidated input/tools/media/thinking/control rewrites, original-text replacement, reordering, netted growth, media replacement, output-cap expansion or omission, Completions `n` changes, Google nested control rewrites (including `candidateCount`, `cachedContent`, `responseModalities`), Responses hidden-input fields (`previous_response_id`, `conversation`, `truncation`), non-stream/background requests and selected-model changes are rejected with zero HTTP. Nunc does not ship a per-provider rewrite mapper or extension allowlist. Temporary payload injection does not backfill a frozen maintenance source. Other extensions may add or drop their own context messages; load order is not a Nunc requirement. Arbitrary deletion or rewrite of Nunc memory carriers is unsupported and is not fully detected. Registering a replacement or wrapping the current Provider between settled requests is tested; arbitrary concurrent registration cannot establish compatibility.
- Capacity estimates are planning heuristics, not proof of provider tokenization, cache reuse, cost or memory quality. Native images need an operator-justified bound.
- Resume reads the selected saved M/K. New sessions start empty; tree/fork/clone follow the selected path. No cross-session memory cache exists. Legacy external summaries enter M as one slot; malformed Nunc snapshots fail explicitly.

`nunc:admission` reports classification, delegation/rejection, estimates and optional payload mode/categories without bodies, headers, credentials or extension paths. `nunc:maintenance` reports a detached attempt result; it is **not a persistence receipt**. Observe native `session_compact` and JSONL for persistence. `nunc:diagnostic` reports configuration/preparation failures. Notification consumers cannot change a candidate.

The [complete check](DEVELOPMENT.md) executes stock CLI/RPC and a real PTY/TUI, native transports against loopback SSE, repeated overlapping rollovers, queues/future images, cancellation, lifecycle and public composition. Public-SDK component fixtures supplement these tests. Codex coverage uses fictional native stored OAuth, the actual Codex serializer/zstd/SSE parser and real stock tool/compaction calls. Pi's existing credential owner performs normal lookup/refresh/persistence; Nunc and its runner never copy, export or manage credentials. Producer tests never read real authentication. All service responses in these mechanical checks are controlled. [Separately authorized continuation observations](LIVE.md) and acceptance of the original core and subsequent compatibility work are recorded in the completed plan history. That evidence does not prove the unimplemented UI. Its native TUI, manual-save and context-observation checks are specified in [UI.md](UI.md); reuse unaffected observations and verify changed behavior on the integrated candidate.
