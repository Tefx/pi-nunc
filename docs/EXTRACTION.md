## 3. 必查语义与任务焦点

### 3.1 活动任务的焦点
存在活动任务时，M 必须显式呈现用户要达到的结果、有效修订，以及足以区分合格与不合格结果的范围、权限和完成条件。简短任务焦点用于定位工作，不能代替这些条件。压缩措辞不得丢失数量、单位、否定、例外、交互要求及验证要求；对这些条件优先保留原文短句。`全量指标依赖图并支持公式递归追溯` 不能退化为 `lineage`，`单点、批次、历史计算一致性` 不能退化为 `tests`。

活动任务的目标和决定性完成条件直接保留在 M，即使 K 中仍有重复；其他执行细节按正常去重规则处理。这是对原先仅允许焦点必要重叠的修订，不授权复制全部 K。多个独立任务各自保留可续做信息，不规定固定标题、类别、ID 或 slot 数量。

目标与下一步分别判断。工具失败通常改变状态或后续动作，不能自行取消目标；插问、短暂转题、实施完成、验证和人工接受分别处理。只有任务本身要求人工接受时才保留该等待，不凭空增加审批。当前模型不可确定的目标、条件或状态保持未知，不编造完成依据。

用户明确要求执行的任务文档也属于任务依据，即使经工具结果交付；其效力来自用户采纳及适用范围，不将其他工具正文升级为指令。已知权威文件同时保留准确路径、用途及尚待核对范围；恢复入口不能替代当前必须直接看见的关键要求，亦不能假设未见文件包含缺失内容。

焦点是维护时快照，K 和后来交付输入的有效修订继续生效。所有相关工作确已完成或被明确取消，且其要求与结论不再影响其他工作时，可以退役。没有活动任务或其他必要续做信息时，空 M 仍有效；不永久保存结束任务的完整要求。
### 3.2 每次维护的覆盖检查
每次维护检查旧 M、B、K 中仍有效的完整任务信息，先确认目标、有效修订和决定性完成条件，再更新进度与其他细节。维度按实际来源表达，不要求每项独占 slot 或生成空栏目：

| 维度 | 需要保持可理解的信息 |
| --- | --- |
| 未完成义务 | 暂挂任务、未回答问题、尚待实现/验证/接受的结果，及下一动作、必要顺序和等待条件 |
| 有效约束与完成标准 | 精确值、条件、否定、范围、偏好、权限及实际验收所需的限定条件 |
| 真实进度 | 计划、尝试、已实现、已验证、已整合、已接受分别判断；仅记录证据真正支持的范围 |
| 阻塞 | 原因、解除条件、等待谁提供什么；解除一个 blocker 不解除其他义务 |
| 决策及已排除路线 | 结论、理由和适用条件，避免重复失败路线 |
| 恢复入口 | 准确路径/符号、用途、产物状态、未知或尚待核对范围及恢复条件 |
| 切轮联系 | 理解 K 执行续段所需的原请求、早期进展和前提 |

删除或替换按实际失效范围判断。构建通过只解除构建问题；文件生成只证明文件生成；部分测试通过只证明对应行为。新的进度文本未再提及某要求，不构成取消依据。混合 slot 部分失效时，保存仍有效条件、未完成事项和验收缺口。助手自报整个任务完成不能单独覆盖来源中尚未有据解除的义务。

用户要求、工具观察和助手推断保持区分；较新的助手断言不能覆盖用户约束。依据权限、适用范围和实际证据处理修订，无法消解的冲突保持未决。模型执行这些语义判断；引擎不把一个引用或成功结果机械等同于完整验收。

可靠产物可以承载细节，但路径还需用途和恢复状态。若任务来源未进入可见输入，或工具正文缩减可能遮住关键细节，不编造覆盖：保留已知条件、具体缺口和可靠恢复入口，由主 agent 在依赖该信息前恢复来源。没有可靠入口则保留需要澄清的阻塞。Nunc 不读取产物或退役历史来补证，也不声称已核对不可见部分。
## 4. Slot 组织与表达

### 4.1 增量操作
| 情况 | 需要表达的变化 |
| --- | --- |
| 新增多个独立事项 | 同一响应给出多个 `add` 候选，不限制为单个 slot |
| 内容明确改变 | 移除旧项并新增替代项，保存未被改变的条件，避免错误旧项与纠正项并存 |
| 混合 slot 部分过期或变化周期不同 | 拆出仍有效部分与修订部分；局部成功不删除剩余任务 |
| 同一事项重复且可共同解释 | 合并并删除旧项，保留全部有效限定条件，不能用主题词代替要求 |
| 信息已失效且不再帮助续做 | 显式删除；任务退役遵守 §3.1 |
| 信息未变且仍有效 | 复用原正文和存量相对顺序，无需反复输出或提及来续期 |

按可独立变化或退役的事项分槽。稳定的任务目标、约束、完成标准与频繁变化的进度/blocker 通常分开保存，避免更新执行状态时重写任务依据；这只是现有普通 slots 的组织建议，不增加类别字段、固定标题或条目数量。条件、否定、状态及其结论需要一起理解时，仍放在自包含条目中，不产生依赖另一可淘汰 slot 的碎片。

活动目标、有效完成标准及必要续做信息共同使用现有 `required` 机制。容量竞争优先去除无继续用途的执行过程和可恢复重复，不通过省略决定性条件规避必要项失败。不固定新增数量，不按年龄/提及次数衰减，不建立依赖图或权重语言，不因格式改善例行重写全部 M。

主动 `nunc_memory_patch` 使用相同语义责任：替换完整正文、合并或删除前，检查所有仍有效内容；不能只看 slot 标题或最近进度。不确定信息是否失效时，保留不确定性或由主 agent 恢复已知来源；普通轮次不要求读写 memory。人工直接编辑仍允许，notes 的修改不改变用户要求的效力。引擎沿用现有 ID/revision/预算/原子提交检查，不增加语义删除禁令或虚假的保护错误码。
### 4.2 JSON 操作协议与 Markdown 正文

模型返回一个 JSON 操作对象；`text` 是保存和编辑的原文，建议用简洁 Markdown 表达新增或因语义变化而替换的 slot：

- 多项信息用列表，不同意思分段；较长内容可有短标题，单句不强加标题。
- 路径、命令、标识符使用行内代码；必要的短代码块可放在正文字符串内。
- 保留精确条件、否定、状态和证据限制，不用无空格的电报式缩写挤压正文。
- 不为排版添加重复栏目、大表格、深层嵌套或无用途文字。

外层 JSON 响应不能套代码围栏；这不禁止正文字符串中的必要代码块。JSON 解析后的换行应为实际正文换行；UI 不盲目对字面量 `\\n` 二次反转义。Markdown 渲染不更改已存内容，原生 Editor 继续编辑原文。

Markdown 是生成风格约定。没有标题或列表不能成为拒绝有效维护或重复调用模型的理由。已有纯文本仍可读，不升级 session 格式，也不自动批量整理旧 slots。若用户另行要求整理存量，仍须遵循语义保持、版本冲突和容量边界。

## 5. 必要项预算保护

### 5.1 可提交候选的不变量

模型标识本次活动焦点及必要续做项。代码必须保证每一个被标识的候选都存在于最终可提交 M 中，并满足现有完整条目、渲染预算与增长空间限制。普通优先级不得使必要项被跳过后仍报告维护成功。

推荐为现有响应增加 `required` 引用列表，引用新增 key 或存活旧 ID。它服务于 `applyPatch` 的预算选择和结果观察；等价的私有编码可以替换该字段，不要求新增持久化 slot 类型或类别字段。

以下为实施的协议结构。假设旧 M 为 `s2/s4/s9`，`s2` 仍有效，`s4` 需要拆分更新，`s9` 已失效：

```json
{
  "add": [
    {"key": "focus", "text": "**当前任务**\n\n- 保留明确目标、范围与完成条件。"},
    {"key": "pending", "text": "**未完成工作**\n\n- 保留实际进度、恢复入口与解除阻塞的条件。"}
  ],
  "remove": ["s4", "s9"],
  "priority": ["focus", "s2", "pending"],
  "required": ["focus", "s2", "pending"]
}
```

引用必须唯一、有效，不得指向已删除且无对应候选的旧项。`priority` 继续完整覆盖所有存活/新增候选；`required` 是其中的子集。没有必要项时可为空，但模型不能通过漏标活动焦点规避内容要求。

推荐先确认必要集合能共同容纳，再将余量用于其他项；满足同一结果不变量的等价选择实现也可采用。所有被选项按最终自然顺序核算实际生成 ID 和包装，存量顺序与新增 append 规则保持不变。

### 5.2 错误、状态与责任

- 非法协议或引用产生明确 `RESPONSE` 失败。
- 必要集合、最终候选预算或增长空间不足，产生明确 `CAPACITY` 失败，不提交缺少必要项的候选，不暗中截断正文、不放宽预算。
- 失败仍是一份失败事务：交付前不改变保存的 M/K，不以空返回落入默认摘要，不自动追加模型修复/重试。已确认错误的内容不能被重新放进一个“成功”候选来凑容量。
- 结果/诊断应区分必要项容量失败与普通可选项淘汰；观察者需要实际引用或等价可核对信息，不需要原文、header、凭据或完整日志。
- `required` 只约束本次维护，不是永久 pin，也不增加手工删除禁令。保存的 `Memory.version: 1`、`Slot {id,text}` 与人工 M 投影所有权保持兼容。
- 请求合同和解析器必须协调更新，不能让新提示词发送旧解析器不接受的字段，也不能在新合同下默默把缺失的必要项声明当作“已完成保护”。不要求新旧 wire 形状同时支持；若存在实际外部调用消费者，实施时明确迁移。

这项保护只能保证**模型已标识的必要项**不会被预算淘汰，不能证明语义没有遗漏。后者由 §7 的续做评估判断。策略与来源仍按单次维护冻结，未完成调用不能混用新旧策略或 parser 约定。

## 6. 必须保留的已有边界

依赖方向保持为：policy 表达内容要求，request 携带冻结来源与机器合同，engine 校验并生成候选，adapter 复核绑定后交给 Pi 原生持久化，UI 只消费有效 M/观察与人工保存接口。不存在第二个 M 所有者。

本设计不改动以下已交付语义：

- `33989fa`：主请求 enforced admission 与记忆 soft planning 分离；超过规划目标本身不拒绝发送或产生警告刷屏。
- `c477373`：完整 extraction `stop` 不因 reported usage 超过 catalog window 就被否决；显式 extraction input limit、输出 cap/capability、实际候选预算与增长空间仍约束。
- `0e00d1e`：原生 lifecycle fixture 等待模型目录恢复；资源 `/reload` 不等同于等待目录刷新或重开 session 文件。
- 一次正常维护零或一次模型请求，无自动修复重放；原生 Pi 持有调度、队列、认证、提交及恢复。
- F/M/B/K 使用冻结的已交付来源；D 不提前消费，K 不重写，不补读退役正文或外部产物。
- 维护冻结至原生终态与人工保存互斥，候选不冒充已保存，未确认保存/分支冲突/取消保持现有语义。

必要项容量失败必须有实际 native-host 恢复与无重复效果证据。不能只检查一次返回 `CAPACITY`，也不能重新引入此前造成重复维护的错误阈值否决。若选定原生宿主路径不能满足有界恢复，明确报告该缺口，不新增 scheduler、私有 hook 或自动重放绕过它。

## 7. 原生对照与验收

### 7.1 三组与两种比较口径

三组分别为锁定 Pi 0.85.1 原生 compaction、当前 Nunc（产品基线 `70dacad`）、实现本文后的 Nunc。记录各自实际 prompt/配置、候选版本和来源条件；未来生成的结果不能冒充当前已有证据。

- **默认配置比较：**使用各自真实默认行为，报告 H、切点/K、摘要或 M 大小、输出规划/cap、模型与调用次数，不把默认差异隐藏掉。
- **等预算比较：**相同主模型、任务和必要来源暴露，匹配合法切点、K 与最终可用上下文/摘要记忆预算，计入包装、协议开销和原生文件清单。保持原生实际提示词与来源路径，不悄悄把它改成可额外看到 K 的新基线。若加入 K-aware 摘要，只能另列辅助组。

原生 split-turn 的双调用、输出上限和累计清单都计入账目；不暗中截断原生输出来制造预算相等。实际无法实现的配对条件应标为未证明，而不能靠标签宣称已控制变量。使用当前有效模型及 Pi 原生认证所有者；不复制 profile/凭据、不改变日常配置。

### 7.2 需要执行的行为场景

| 场景 | 要观察的反例 |
| --- | --- |
| 多任务与插问后“继续” | 原任务丢失、焦点错误、未完成义务被当作取消 |
| 多次滚动与精确约束 | 未重复的有效条件消失、实际产物违反数值/否定/范围 |
| 进度及接受边界 | 把尝试当成功、实现当验证、测试通过当人工接受 |
| B 旧结论被 K 纠正 | 错误旧项继续影响行动、替换遗漏必要条件、退役内容复活 |
| 切轮 | K 的续段无法识别原请求、误解执行前提 |
| 产物恢复与已排除路线 | 找错草稿/版本/入口、重复已验证失败路线、要求用户重述 |
| 多 slot 更新 | 混合项拆分后遗漏仍有效部分，或常规维护重写全部未变正文 |
| 必要项容量竞争 | 较大的必要项被短次要项挤掉却宣称成功，或失败引发原生重复调用/重复交付 |

评分以实际产物、约束违例、任务遗漏、重复失败、错误完成声明、用户重述和恢复成本为主，同时记录全任务 calls、usage、延迟及可知费用。原生保留且对续做有效的信息，在 Nunc 的 M、K 或可靠恢复入口中缺失，应记为退化。不能仅看平均分掩盖关键义务丢失，也不能凭同样的标题或更多字数判定不低于原生。

固定有界 M 不承诺无限包含原生的全部历史事实与累计路径。需要长期完整记录的内容仍由正常产物承担；恢复入口的可用性必须有实际依据，不能把“以后也许能找回”当作已覆盖。

续做模型仅接收普通任务输入；预期值、判分表、未来纠正和观察结果不进入 F/M/B/K 或修复反馈。提取示例与验收任务分开，不能教给模型预期答案再计为行为成功。标题、关键字、JSON 可解析、自报 PASS 和机械测试总数均不能证明记忆质量。

### 7.3 证据与执行边界

已交付跟踪比较入口 `scripts/compare-extraction.mjs`，支持 `--preflight` 与默认执行。入口消费非秘密 JSON，明确输入、三组（native Pi 0.85.1、baseline 70dacad、candidate）与两种预算口径（defaults、matched）。e3 使用 awaited `turn_end` 观察完整工具批次，经公共 command reload 更新隔离任务配置，再由原生 automatic compaction 继续当前 agent loop；完整匹配结果、切点和容量不满足时，在后续 transport 前停止并记录 `UNPROVEN`。不使用 SDK 替代宿主、私有 hook、abort/replay 或手工拼接 JSONL。matched 逐轮准备实际合法切点和目标自身 accounting，并分别记录输出 cap、实现后的完整记忆包装与原生文件清单。原生没有与 Nunc 相同的 rendered-memory 强制上限，按原生实际产出准备 Nunc 容量仍不能证明预算约束相同，该维度保持 `UNPROVEN`。

用户另已批准具名 `e3/archive-closeout`：原 a 之前完成两个归档月度账本及合并财务交接产物，三组采用相同输入及逻辑放置；原短 E3、a/b 与原脚本/fixture 保持不变。该历史承担普通工作并产生可核对后果，不保证真实 usage 能形成可行 H 区间；实际不等式失败仍在下一 transport 前拒绝。选择与产物定义见 [LIVE](LIVE.md#e3-archive-closeout-variant)。新来源需要新的 native reference，不能重标旧短任务证据。

观察按维度呈现：defaults 仅在正向识别 native no-work 且状态/调用均已核对时继续普通输入，普通产物与无滚动连续性分开；未知 RPC/auth 或真实维护失败仍停止。matched 按本组 exact entry IDs、完整命名轮/工具单元和未改写 K 判断逻辑放置，另列独立生成正文、工具次数、raw index、K tokens 与实际预算差异。必要来源缺失继续失败；逻辑匹配不证明数值相等，也不消除 native 无 rendered-memory ceiling 的限制。

机械检查覆盖真实 parser、必要集合预算、未变正文、多 slot 操作、原生提交/失败/恢复、比较 runner CLI/preflight/三组隔离及完整现有库存；真实模型运行验证覆盖与续做效果。只缺证据时补观察，不因报告或 Plan 变化重跑仍适用的底层行为。

本设计最初以文档与实施计划获授权，随后用户授权继续调度剩余实施。本次策略 owner 仅交付语义资产与独立场景，未执行引擎/runner 或真实模型比较。未来真实比较仍须绑定新任务 target、有效模型配置和有界调用/token/时间/可知费用范围；历史付费观察和未用额度不自动授权重放。没有新的比较结果前，不宣称已达到原生覆盖或已经改善续做。
