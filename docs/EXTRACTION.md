## 2. 原生 Pi 基线

调研依据为实际安装的 `@earendil-works/pi-coding-agent@0.85.1`。包内路径以 `dist/core/compaction/` 为前缀：

| 源码 / 符号 | 实际要求或行为 | 本设计采用的依据 |
| --- | --- | --- |
| `compaction.js` / `SUMMARIZATION_PROMPT` | Goal（可有多个任务）、Constraints & Preferences、Progress 的 Done/In Progress/Blocked、带理由的 Key Decisions、有序 Next Steps、Critical Context；保留准确路径、函数名和错误信息 | 续做覆盖不能仅剩零散事实或最近动作 |
| `UPDATE_SUMMARIZATION_INSTRUCTIONS` | 默认保留旧目标、约束和重要上下文，纳入新进展并更新下一步；允许移除不再相关信息 | 未完成义务持续有效，状态需要更新，过期信息可以删除 |
| `TURN_PREFIX_SUMMARIZATION_PROMPT` | Original Request、Early Progress、Context for Suffix | K 从执行中途开始时，补足理解续段所需的原请求与前提 |
| `utils.js` / `extractFileOpsFromMessage`、`computeFileLists`；`compact()` | 从 `read/write/edit` 调用的 `path` 累计文件记录，追加 read/modified 清单 | 路径和恢复入口有实际续做价值；调用记录不等于操作成功，也不覆盖任意 shell 文件操作 |
| `utils.js` / `serializeConversation` | 每条工具结果仅保留前 2,000 字符 | 保留 Nunc 的完整来源优势；其有标记缩减仍只在 extraction 实际超限时发生 |

原生普通摘要输出上限为 `min(floor(0.8 × reserveTokens), model.maxTokens)`；默认 reserve 为 16,384 时，普通摘要请求上限为 13,107，仍受实际模型/API 限制。切轮前缀使用另一预算，原生 split-turn 可以产生两次摘要请求。Nunc 当前维护规划默认 `min(8192, model.maxTokens)`，uncapped API 不据此产生输出 cap。比较必须报告这些差异，不能把更大的输出预算算作提示词收益。

原生 structured summary 是比较基线，不要求 Nunc 改成每次重写整份摘要。原生文件清单可能持续增长；本设计不承诺在有界 M 中无限累计所有历史路径。

## 3. 必查语义与任务焦点

### 3.1 活动任务的焦点

存在活动任务时，M 必须显式呈现简短的任务焦点，回答：用户要达到什么结果、哪些完成条件及范围/权限仍有效、当前做到哪里、还有什么未完成或正在等待。多个独立任务可以各有焦点，也可以用能够独立续做的等价组织方式；不规定固定标题、ID、类别枚举或 slot 数量。

目标与下一步分别判断。工具失败通常改变执行状态或后续动作，不能自行取消用户目标。插问、短暂转题、实施完成和人工接受分别处理，不能自动把尚未解除的义务记为已完成。若来源未明确目标或状态，保留相应未知，不编造答案。

焦点是维护时的状态快照；K 或后来实际交付输入中的有效纠正继续生效。允许为简短焦点保留必要的 K 重叠，以便接手者直接定位任务；这不授权复制全部 K。所有相关工作确已完成或被明确取消时，可以退役该焦点。没有活动任务、也没有其他必要工作信息时，空记忆仍有效。

### 3.2 每次维护的覆盖检查

下列维度必须检查，按来源中的实际信息表达，不要求每维独占一个 slot，也不生成空栏目：

| 维度 | 需要保持可理解的信息 |
| --- | --- |
| 未完成义务 | 暂挂任务、未回答问题、尚待验证或接受的结果 |
| 有效约束 | 精确值、条件、否定、适用范围、用户偏好与权限边界 |
| 真实进度 | 计划、尝试、已实现、已验证、已整合、已接受的区别 |
| 阻塞 | 原因、解除条件、等待谁提供什么 |
| 决策及已排除路线 | 结论、必要理由和适用条件，避免重复已失败方案 |
| 恢复入口 | 准确路径/符号、用途、产物状态及继续操作所需的条件 |
| 切轮联系 | 理解 K 中执行续段所必需的 B 中原请求、早期进展和关键前提 |

可靠产物可以承载细节，但只记路径未必足够。例如未完成草稿还需要保留其状态和下一次验证入口。维护不得读取该产物来补证，也不得声称已经核对被省略或不可见的内容。

用户要求、工具观察和助手推断保持区分。纠正按权限、适用范围和实际证据判断；较新的助手断言不能覆盖用户约束。无法消解的冲突保留为未决信息。已有焦点与存量 slot 也要接受检查，不能仅扫描 B 的新事实。

## 4. Slot 组织与表达

### 4.1 增量操作

| 情况 | 需要表达的变化 |
| --- | --- |
| 新增多个独立事项 | 同一响应中给出多个 `add` 候选，不限制为单个 slot |
| 内容明确改变 | 移除旧项并新增替代项，避免错误旧项与纠正项并存 |
| 混合 slot 部分过期或更新频率不同 | 移除旧混合项，拆出仍有效部分与修订后部分 |
| 同一事项重复且可共同解释 | 合并，删除被合并的旧项 |
| 信息已失效且不再帮助续做 | 显式删除 |
| 信息未变且仍有效 | 复用原正文和存量相对顺序 |

按可独立变化或退役的事项分槽。条件、否定、状态及其结论需要一起理解时，保留在同一条中；不要产生必须依赖另一个可淘汰 slot 才能解释的碎片。完成过程可以退出，仍然影响后续工作的约束、结论、验收缺口和失败原因继续保留。

不固定每轮新增数量，不按年龄/提及次数衰减，不建立依赖图或权重语言，不为重新排版例行重写全部 M。增量协议继续明确引用所有存活项与新增项，遗漏不能被解释为删除。

### 4.2 JSON 操作协议与 Markdown 正文

模型返回一个 JSON 操作对象；`text` 是保存和编辑的原文，建议用简洁 Markdown 表达新增或因语义变化而替换的 slot：

- 多项信息用列表，不同意思分段；较长内容可有短标题，单句不强加标题。
- 路径、命令、标识符使用行内代码；必要的短代码块可放在正文字符串内。
- 保留精确条件、否定、状态和证据限制，不用无空格的电报式缩写挤压正文。
- 不为排版添加重复栏目、大表格、深层嵌套或无用途文字。

外层 JSON 响应不能套代码围栏；这不禁止正文字符串中的必要代码块。JSON 解析后的换行应为实际正文换行；UI 不盲目对字面量 `\\n` 二次反转义。Markdown 渲染不更改已存内容，原生 Editor 继续编辑原文。

Markdown 是生成风格约定。没有标题或列表不能成为拒绝有效维护或重复调用模型的理由。已有纯文本仍可读，不升级 session 格式，也不自动批量整理旧 slots。若用户另行要求整理存量，仍须遵循语义保持、版本冲突和容量边界。

## 5. 必要项预算保护

### 5.1 可提交候选的不变量

模型标识本次活动焦点及必要续做项。代码必须保证每一个被标识的候选都存在于最终可提交 M 中，并满足现有完整条目、渲染预算与增长空间限制。普通优先级不得使必要项被跳过后仍报告维护成功。

推荐为现有响应增加 `required` 引用列表，引用新增 key 或存活旧 ID。它服务于 `applyPatch` 的预算选择和结果观察；等价的私有编码可以替换该字段，不要求新增持久化 slot 类型或类别字段。

以下仅为下一版协议示意，当前解析器尚不接受 `required`。假设旧 M 为 `s2/s4/s9`，`s2` 仍有效，`s4` 需要拆分更新，`s9` 已失效：

```json
{
  "add": [
    {"key": "focus", "text": "**当前任务**\n\n- 保留明确目标、范围与完成条件。"},
    {"key": "pending", "text": "**未完成工作**\n\n- 保留实际进度、恢复入口与解除阻塞的条件。"}
  ],
  "remove": ["s4", "s9"],
  "priority": ["focus", "s2", "pending"],
  "required": ["focus", "s2", "pending"]
}
```

引用必须唯一、有效，不得指向已删除且无对应候选的旧项。`priority` 继续完整覆盖所有存活/新增候选；`required` 是其中的子集。没有必要项时可为空，但模型不能通过漏标活动焦点规避内容要求。

推荐先确认必要集合能共同容纳，再将余量用于其他项；满足同一结果不变量的等价选择实现也可采用。所有被选项按最终自然顺序核算实际生成 ID 和包装，存量顺序与新增 append 规则保持不变。

### 5.2 错误、状态与责任

- 非法协议或引用产生明确 `RESPONSE` 失败。
- 必要集合、最终候选预算或增长空间不足，产生明确 `CAPACITY` 失败，不提交缺少必要项的候选，不暗中截断正文、不放宽预算。
- 失败仍是一份失败事务：交付前不改变保存的 M/K，不以空返回落入默认摘要，不自动追加模型修复/重试。已确认错误的内容不能被重新放进一个“成功”候选来凑容量。
- 结果/诊断应区分必要项容量失败与普通可选项淘汰；观察者需要实际引用或等价可核对信息，不需要原文、header、凭据或完整日志。
- `required` 只约束本次维护，不是永久 pin，也不增加手工删除禁令。保存的 `Memory.version: 1`、`Slot {id,text}` 与人工 M 投影所有权保持兼容。
- 请求合同和解析器必须协调更新，不能让新提示词发送旧解析器不接受的字段，也不能在新合同下默默把缺失的必要项声明当作“已完成保护”。不要求新旧 wire 形状同时支持；若存在实际外部调用消费者，实施时明确迁移。

这项保护只能保证**模型已标识的必要项**不会被预算淘汰，不能证明语义没有遗漏。后者由 §7 的续做评估判断。策略与来源仍按单次维护冻结，未完成调用不能混用新旧策略或 parser 约定。

## 6. 必须保留的已有边界

依赖方向保持为：policy 表达内容要求，request 携带冻结来源与机器合同，engine 校验并生成候选，adapter 复核绑定后交给 Pi 原生持久化，UI 只消费有效 M/观察与人工保存接口。不存在第二个 M 所有者。

本设计不改动以下已交付语义：

- `33989fa`：主请求 enforced admission 与记忆 soft planning 分离；超过规划目标本身不拒绝发送或产生警告刷屏。
- `c477373`：完整 extraction `stop` 不因 reported usage 超过 catalog window 就被否决；显式 extraction input limit、输出 cap/capability、实际候选预算与增长空间仍约束。
- `0e00d1e`：原生 lifecycle fixture 等待模型目录恢复；资源 `/reload` 不等同于等待目录刷新或重开 session 文件。
- 一次正常维护零或一次模型请求，无自动修复重放；原生 Pi 持有调度、队列、认证、提交及恢复。
- F/M/B/K 使用冻结的已交付来源；D 不提前消费，K 不重写，不补读退役正文或外部产物。
- 维护冻结至原生终态与人工保存互斥，候选不冒充已保存，未确认保存/分支冲突/取消保持现有语义。

必要项容量失败必须有实际 native-host 恢复与无重复效果证据。不能只检查一次返回 `CAPACITY`，也不能重新引入此前造成重复维护的错误阈值否决。若选定原生宿主路径不能满足有界恢复，明确报告该缺口，不新增 scheduler、私有 hook 或自动重放绕过它。

## 7. 原生对照与验收

### 7.1 三组与两种比较口径

三组分别为锁定 Pi 0.85.1 原生 compaction、当前 Nunc（产品基线 `70dacad`）、实现本文后的 Nunc。记录各自实际 prompt/配置、候选版本和来源条件；未来生成的结果不能冒充当前已有证据。

- **默认配置比较：**使用各自真实默认行为，报告 H、切点/K、摘要或 M 大小、输出规划/cap、模型与调用次数，不把默认差异隐藏掉。
- **等预算比较：**相同主模型、任务和必要来源暴露，匹配合法切点、K 与最终可用上下文/摘要记忆预算，计入包装、协议开销和原生文件清单。保持原生实际提示词与来源路径，不悄悄把它改成可额外看到 K 的新基线。若加入 K-aware 摘要，只能另列辅助组。

原生 split-turn 的双调用、输出上限和累计清单都计入账目；不暗中截断原生输出来制造预算相等。实际无法实现的配对条件应标为未证明，而不能靠标签宣称已控制变量。使用当前有效模型及 Pi 原生认证所有者；不复制 profile/凭据、不改变日常配置。

### 7.2 需要执行的行为场景

| 场景 | 要观察的反例 |
| --- | --- |
| 多任务与插问后“继续” | 原任务丢失、焦点错误、未完成义务被当作取消 |
| 多次滚动与精确约束 | 未重复的有效条件消失、实际产物违反数值/否定/范围 |
| 进度及接受边界 | 把尝试当成功、实现当验证、测试通过当人工接受 |
| B 旧结论被 K 纠正 | 错误旧项继续影响行动、替换遗漏必要条件、退役内容复活 |
| 切轮 | K 的续段无法识别原请求、误解执行前提 |
| 产物恢复与已排除路线 | 找错草稿/版本/入口、重复已验证失败路线、要求用户重述 |
| 多 slot 更新 | 混合项拆分后遗漏仍有效部分，或常规维护重写全部未变正文 |
| 必要项容量竞争 | 较大的必要项被短次要项挤掉却宣称成功，或失败引发原生重复调用/重复交付 |

评分以实际产物、约束违例、任务遗漏、重复失败、错误完成声明、用户重述和恢复成本为主，同时记录全任务 calls、usage、延迟及可知费用。原生保留且对续做有效的信息，在 Nunc 的 M、K 或可靠恢复入口中缺失，应记为退化。不能仅看平均分掩盖关键义务丢失，也不能凭同样的标题或更多字数判定不低于原生。

固定有界 M 不承诺无限包含原生的全部历史事实与累计路径。需要长期完整记录的内容仍由正常产物承担；恢复入口的可用性必须有实际依据，不能把“以后也许能找回”当作已覆盖。

续做模型仅接收普通任务输入；预期值、判分表、未来纠正和观察结果不进入 F/M/B/K 或修复反馈。提取示例与验收任务分开，不能教给模型预期答案再计为行为成功。标题、关键字、JSON 可解析、自报 PASS 和机械测试总数均不能证明记忆质量。

### 7.3 证据与执行边界

实现需提供当前可执行的 tracked 比较/观察入口，明确输入、三组选择、预算口径、来源及终态记录、隔离与清理。本文不假定现有 runner 已支持这些参数；实施计划须据实际 CLI 决定扩展边界。

机械检查覆盖真实 parser、必要集合预算、未变正文、多 slot 操作、原生提交/失败/恢复及完整现有库存；真实模型运行验证覆盖与续做效果。只缺证据时补观察，不因报告或 Plan 变化重跑仍适用的底层行为。
